Kraken: an AI expense splitter for Android and iPhone

Kraken lets a group of friends split costs by typing, talking, or photographing a bill. An on-device rule engine handles each request first; Gemini sees it only when the rules can't produce a valid action. Either way the app validates the action and does every rupee calculation itself, in whole paise. This version plans a private release for you and 3–4 friends, installed directly from Xcode and as an Android APK, with no store listing and no paid accounts.

~16 wkssolo build; friends using it from week 15, Gmail in week 17
5 peopleyou + 3–4 friends; only you connect Gmail
Rules → AIGemini only as the second attempt
$0 / moeverything on free tiers, no domain, no store fees

What this review recommends

Flutter + Clean Architecture on the phone, Firebase free tiers (Auth, Firestore, AI Logic, FCM, Hosting) as the platform, and a Dart back end on Cloud Run at its free *.run.app address. A pure-Dart intent package parses commands, bills and receipts by rules before anything reaches Gemini, and the shared ledger package does the money maths on both sides. At five users that keeps Gemini to about 5 requests a day, well inside the free tier.

Non-functional requirements

  • Money accuracy: all amounts are int paise; leftover paise go to the first members (₹100 ÷ 3 = 33.34 / 33.33 / 33.33).
  • Speed: no screen over 1 s on a mid-range Android; Insights over 1,000 expenses under 1 s.
  • AI quality: nightly eval ≥90% exact-match; median reply time tracked.
  • Reliability: works offline, syncs later; ≥99.5% crash-free sessions.
  • Security: App Check on Firestore, AI and API; rules test per collection; no secrets in the binary.
  • Privacy: DPDP notice and consent, export and deletion; no email bodies or bill photos stored.
  • Accessibility: TalkBack / VoiceOver complete add-expense and settle up; 200% text.

Gaps between the design and the guide

  • Desktop screens: 7 of 21 artboards are desktop (dashboard, scan split, insights, Gmail). The guide is phones only. Treat them as post-launch; the clean-architecture domain layer is reused unchanged when Flutter web arrives.

  • Store work: Phase 8's closed test, listings, store privacy forms and review are skipped; the privacy consent and delete-account work stays because your friends' data is still real.
  • Export button on Group and Totals tab: not in any phase. Add CSV export to Phase 7.

Rules first, then Gemini

The rule engine or, as a fallback, Gemini proposes an action. ActionValidator checks group, members, amount > 0 and that shares sum, then ledger computes paise. Every write shows an Undo card.

Balances are derived, never stored

Balances are recomputed from expenses and payments by ledger. A last-write-wins conflict on one expense can't corrupt a stored total, because there isn't one.

Same maths on both sides

packages/ledger and packages/contracts are imported by the app and the API, so invite claims and reminders compute amounts exactly as the phone does.

03 · Front end

Flutter with Clean Architecture

The rules

  • Domain is pure Dart: no Flutter, no Firebase imports. It holds entities (Group, Expense, Money), the sealed AgentAction hierarchy, use cases, and repository interfaces.
  • Data implements those interfaces with Firestore, AI Logic and the API, mapping DTOs to entities. Swapping AI Logic for a server proxy later is a data-layer change only.
  • Presentation uses Riverpod Notifiers that call use cases; widgets never touch a repository.
  • Errors cross layers as a sealed Result<T> with typed Failures, so the agent can repeat a refusal in plain words.
  • Tests follow the layers: domain and ledger by unit test, data against the Firestore emulator, presentation by widget test, flows by integration_test.

04 · Rules first, Gemini second

Every request tries the rule engine before the AI

Typed text, voice transcripts, bill photos and Gmail receipts all go through deterministic, on-device rules first. Gemini gets a request only when the rules can't produce an action that passes the validator. Everyday commands never leave the phone, cost nothing and answer instantly. That keeps a group of five inside the free tier.

When the rules are allowed to act

A wrong guess saves a wrong amount; an escalation costs one free request. So the rules act only when all of these hold:

  • exactly one intent matched
  • the amount has one reading (“2.5k” yes, “25 or 30” no)
  • every name resolves to exactly one group member
  • the group is known, from the current screen or by name
  • the validator accepts the action

Anything else escalates. If only the amount or payer is missing, the rules ask a scripted question instead, which costs nothing.

Keeping Gemini calls rare

  • One request per fallback. The app writes the reply from a template, so there is no second round trip with tool results.
  • Small prompts. Only the current group's names and recent amounts are sent, with no chat history.
  • Daily guard. A Firestore counter stops at 15 requests a day for the project and 5 per person, below the free limit. Past it, Kraken says AI is off for today and shows phrasings the rules understand.
  • Misses become rules. Each fallback is saved to the sender's own ruleMisses list, so common phrasings get new patterns.
  • Measured. The test set reports rules hit rate, rules errors (must be zero) and combined accuracy.
// features/agent/domain/interpret_command.dart (pure Dart)
final class InterpretCommand {
  InterpretCommand(this._rules, this._gemini, this._validator, this._quota);
  final RuleInterpreter _rules;     // packages/intent, on device
  final AgentGateway _gemini;       // data layer: Firebase AI Logic
  final ActionValidator _validator;
  final AiQuota _quota;             // daily guard in Firestore

  Future<Outcome> call(String text, LedgerSnapshot s) async {
    // 1st attempt: always rules
    switch (_rules.parse(text, s)) {
      case Confident(:final action):
        if (_validator.validate(action, s) case Ok(:final value)) {
          return Outcome.done(value, by: Source.rules);
        }
      case NeedsSlot(:final question):
        return Outcome.ask(question);           // scripted chips, no AI
      case NoMatch():
        break;
    }
    // 2nd attempt: Gemini, once
    if (!await _quota.tryTake()) return Outcome.aiOffToday();
    final proposed = await _gemini.propose(text, s.compactForGroup());
    return switch (_validator.validate(proposed, s)) {
      Ok(:final value) => Outcome.done(value, by: Source.gemini),
      Err(:final failure) => Outcome.refused(failure),
    };
  }
}

Work this adds: 3 days in Phase 3 (lexicon, patterns, slot filling, test cases), 2 days in Phase 5 (ML Kit and the bill parser), 1 day in Phase 9 (sender templates) and half a day in Phase 7 (keyword categories). The timeline below includes them.

05 · Back end

Dart, but on Cloud Run

You asked for a Dart back end. The guide plans Dart Cloud Functions, which Firebase still marks experimental: HTTP and callable only, no Firestore triggers, not listed in the console. A Dart server in a container on Cloud Run keeps the shared ledger and avoids those limits.

A · Dart Cloud Functions

Experimental
  • Least setup, deploys with firebase deploy
  • HTTP / callable only; no triggers
  • Must call by URL; invisible in console
  • Risk the experiment changes mid-build

B · Dart Frog on Cloud Run

Recommended
  • Stable runtime; AOT binary starts fast
  • Same code shape as A; middleware for auth and App Check
  • Revisions with traffic split and one-click rollback
  • Free tier covers launch traffic

C · Serverpod

Not now
  • Full Dart stack with typed client
  • Needs Postgres and its own auth; replaces Firestore
  • Loses offline sync and live listeners
  • Too much rebuild for one developer

Five calls for you to make

1

Cloud Run with a card on file, or Render with no card? Cloud Run is recommended: $0 at this size, same Google project, quick first response. Render's free tier needs no card but is slow after idle.

2

Are you and your friends OK with the free tier's data terms? If not, the paid tier costs roughly ₹25 a month at five users and keeps prompts out of Google's training.

3

When a rule is missing just one detail, ask first or go straight to Gemini? Asking first is recommended: it's free and instant, and Gemini handles only messages the rules can't read at all.

4

iPhone sign-in without Universal Links: bounce page or Google sign-in? The bounce page keeps the chat email flow from the design. Google sign-in is simpler but changes the onboarding screen.

5

Desktop screens later, as Flutter web? The domain and rules layers carry over unchanged; only presentation is new.
